Booking Tag Cleanup

Replace the many inconsistent "call booked" tags with one standard pair, then remove the old tags so nobody can apply them again. Five phases, each ending at a checkpoint where you report to Tommy and wait for approval.

Prepared for ACTA Football Version 1.1 Calendars read from the live CRM, 30 Sep 2026

The problem

Several past CRM specialists, plus an older booking system (iClosed), each tagged bookings their own way. Not all iClosed appointments were migrated, so some contacts who really did book have no appointment on record, only a tag. The result: ACTA cannot reliably filter contacts by whether they have or haven't booked a call.

How ACTA's sales process works

There are two sales calls. The PDS (Player Development Session) is the first call. The PEM (Player Evaluation Meeting) is the second call, the closing call. Nobody reaches a PEM without a PDS first.

Anything in this typeface is a literal value in the CRM. Type it exactly.

Rules

Decided by ACTA

1 · Every booking tag gets replacedEvery contact carrying any old booking tag must end up with a standard booking tag. The only question is which one. Do not drop a contact because there is no appointment on record, because iClosed bookings were not all migrated.
2 · Decide from evidence, in this order(a) The contact's appointment history on the five calendars above. (b) If there is no appointment on record, the rest of the contact's history: what the old tag means, opportunity and pipeline stage, notes, conversations. (c) If it's still unclear whether the call was a closing call, use pds-booked.
3 · PEM implies PDSAny contact with pem-booked must also have pds-booked. This includes contacts who have pem-booked today.
4 · Booking tags onlyOnly tags that mean a call was booked are in scope. Leave every other tag exactly as it is.
5 · Ask, don't guessIf you can't tell what an old tag means, ask Tommy before mapping it.
6 · Add first, remove laterNever remove or delete a tag until the replacement tags are in place and Tommy has approved in writing.
Process

Five phases

Each checkpoint means: send Tommy the listed deliverables in writing (a Google Sheet is fine), then stop until he approves. Include counts, not just descriptions.

Phase 0 · Backup

  1. Export every contact with all fields and tags to CSV before changing anything. Share it with Tommy.

Phase 1 · Audit (no changes)

  1. Tag inventory. List every tag in the account that indicates a booked call. For each one, give its contact count, what it means, and your proposed mapping: pds-booked, pem-booked + pds-booked, or unused (0 contacts). State the evidence behind each mapping, e.g. "91% of these contacts have a PEM-calendar appointment".
  2. Contact mapping. For each contact carrying an old tag, record which standard tag(s) they will receive and which rule decided it (2a, 2b or 2c). Give totals per standard tag, and list separately every contact decided under 2c.
  3. Workflow inventory. Find every workflow, active or draft, that adds, removes, triggers on or filters on any tag from step 1, or that runs on any of the five calendars. For each one give: name, on/off, trigger, what it does, and which tag it adds. Flag duplicates and overlaps, and recommend retire, merge or keep for each.
  4. Trigger check. List every workflow that triggers when pds-booked or pem-booked is added. Bulk-adding these tags must not send messages, move opportunities or notify staff. Say exactly how you will prevent that.
  5. Calendar check. For each of the five calendars, confirm what a new booking tags today. The target: PDS calendars add pds-booked; PEM calendars add pem-booked and pds-booked.
Checkpoint 1

Send steps 1 to 5. Wait for Tommy's approval of the mapping and the workflow changes before touching anything.

Phase 2 · Fix the source

  1. Make the approved workflow changes, so that nothing adds an old tag any more and every new booking adds the correct standard tags.
  2. Test with a test contact: book once on each of the five calendars. Confirm the right tags are added and nothing unexpected fires. Delete the test contact afterwards.
Checkpoint 2

Send what you changed and the five test results.

Phase 3 · Add the standard tags

  1. Put the safeguard from Phase 1 step 4 in place.
  2. Add the standard tags per the approved mapping, including the PEM-implies-PDS rule.
  3. Remove the safeguard and confirm those workflows are running normally again.
Checkpoint 3

For each standard tag, send the count before and after. Confirm that every contact holding an old booking tag now holds a standard one, and list any exceptions. Wait for written approval to remove the old tags.

Phase 4 · Remove old tags from contacts

  1. Remove every old booking tag from every contact. Leave all other tags as they are.
Checkpoint 4

Confirm that every old booking tag now has 0 contacts, and that the standard tag counts have not changed since Checkpoint 3.

Phase 5 · Delete the old tags from the CRM

  1. First confirm that no workflow still references any old tag. Deleting a tag a workflow still uses breaks that step.
  2. Delete the old booking tags from the tag list so nobody can apply them again. Include the unused ones.
Final report

Send the tags deleted, the final counts for the standard tags, and confirmation that a fresh test booking on each calendar still tags correctly.

Scope

Done means

  • Filtering by pds-booked shows everyone who has ever booked a sales call, and pem-booked shows everyone who booked a closing call.
  • No old booking tag exists in the account, and no workflow can recreate one.
  • Out of scope: every tag that is not a booking tag, and pipeline or stage changes (those are covered by the separate automation spec).
